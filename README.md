# DayTrace

## Идея и аудитория

DayTrace помогает восстановить рабочий день за компьютером: какие программы и вкладки были открыты, сколько времени заняла работа и когда возникали перерывы. Проект предназначен для студентов, программистов, фрилансеров и других людей, которые переключаются между несколькими задачами и хотят понимать, куда уходит время.

В дальнейшем приложение будет объединять связанные действия в смысловые сессии с помощью языковой модели: например, PDF с заданиями, учебную лекцию и обсуждение задач — в занятие «Подготовка к экзамену».

## Тип проекта

Настольное приложение для Windows с расширением Chrome. История хранится локально на компьютере пользователя. Постоянная запись экрана не предусмотрена.

## Цель и задачи

**Цель:** создать приложение, которое автоматически собирает историю активности и помогает пользователю анализировать свой день без ручного запуска таймеров.

Для нулевой версии нужно:

- получать активное приложение и заголовок окна Windows;
- получать контекст активной вкладки Chrome;
- учитывать длительность работы, бездействие, блокировку и паузу сбора;
- сохранять историю в SQLite и восстанавливать её после перезапуска;
- показывать историю выбранного дня и статистику по приложениям;
- добавить настройки порога бездействия и исключения приложений и сайтов.

После нулевой версии планируются AI-классификация, смысловые сессии и интеллектуальные отчёты. [Задачи первого этапа на шесть человек](TASKS.md) вынесены в отдельный файл; участников команда назначает самостоятельно.

**Текущее состояние:** подготовлен каркас — окно WPF, модель интервала и SQL-схема. Сбор активности, работа с базой, расширение и полноценные экраны пока не реализованы. Перечисленные выше возможности — план разработки.

## Структурные части и технологии

| Часть | Технологии | Назначение |
|---|---|---|
| Интерфейс | C#, WPF, .NET 8 | История дня, сводная статистика и настройки |
| Сборщик Windows | C#, Windows API | Активное окно, процесс, бездействие и блокировка |
| Общая логика | C# | Модели данных и правила учёта интервалов |
| Хранение | SQLite | Локальная история и выборки для статистики |
| Расширение Chrome | TypeScript, Manifest V3, Chrome API | Контекст активной вкладки |
| Связь браузера с приложением | C#, Native Messaging и локальный канал | Передача событий расширения в настольное приложение |
| AI-анализ — следующий этап | API языковой модели | Группировка действий в занятия и текстовые отчёты |

Отдельный сервер для нулевой версии не требуется. API языковой модели пока не подключён, данные во внешнюю модель не отправляются.

## Запуск и проверка

### Что установить

- Windows 10 или 11.
- .NET 8 SDK для сборки и запуска каркаса.
- Git для скачивания репозитория либо скачать его ZIP с GitHub и распаковать.

Chrome понадобится для проверки будущего расширения. Сейчас расширения в рабочем виде нет, устанавливать его пока нечего.

### Как запустить текущий каркас

В PowerShell:

```powershell
git clone https://github.com/b450b/DayTrace.git
cd DayTrace
dotnet build src/DayTrace.Desktop -c Release
dotnet run --project src/DayTrace.Desktop
```

Если проект скачан архивом, откройте PowerShell в распакованной папке с README и выполните последние две команды.

**Ожидаемый результат:** сборка завершается успешно, открывается окно «DayTrace» с заголовком «История дня» и сообщением об отсутствии записей. Это проверка запуска каркаса: сбор данных, переключение дат и статистика пока недоступны.

## Подсказки для жюри

### Что можно проверить сейчас

1. Собрать и запустить каркас по инструкции выше.
2. Убедиться, что открывается окно с заглушкой истории.
3. Посмотреть структуру исходников и [распределение работ](TASKS.md).

Тестовая учётная запись и API-ключ не нужны. Файл `tests/fixtures/demo.csv` содержит вымышленные данные для разработки; автоматического импорта в интерфейс пока нет.

### Сценарий приёмки будущей нулевой версии

1. Включить сбор, поработать в PDF, переключиться между двумя вкладками Chrome и вернуться в PDF.
2. Проверить порядок интервалов и отсутствие двойного учёта времени.
3. Дождаться порога бездействия, затем продолжить работу: перерыв должен учитываться отдельно.
4. Поставить сбор на паузу и проверить, что новые действия не записываются.
5. Проверить исключения приложений и сайтов: их контекст не должен сохраняться.
6. Перезапустить приложение: история должна сохраниться, суммы по приложениям — совпасть с интервалами.
7. Открыть пустой день: история и статистика должны быть пустыми.

Этот сценарий описывает критерии готовности v0.0, а не уже доступные функции. Специальные читы или режим игры не требуются: DayTrace — приложение для учёта активности.

Для демонстрации используем вымышленные данные. Личные истории, базы и ключи в репозиторий не добавляем; содержимое экрана и нажатые клавиши не записываем.
